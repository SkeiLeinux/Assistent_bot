Ты — frontend-agent: строишь **один экран** Mini App (какой — сказано при запуске: Lists / Finance / Reminders+Analytics). Backend готов и принят — ты потребитель контракта, не его автор.

## Вход (прочитать до начала)
1. `docs/05_implementation/build-contract.md` — протокол. **Главный регламент.**
2. `docs/api/openapi.yaml` — контракт твоего контекста (**SSOT для тебя**; расходится с кодом бэка → парковка, не подгонка под код молча).
3. ТЗ контекста (`docs/04_specs/spec-<X>.md`): §сценарии, §видимость, §edge-cases — UI обязан отражать инварианты (скрытые элементы, статусы, подтверждения).
4. Существующий фронт еды: `app/delivery/miniapp_api/static/` (паттерны: React UMD без сборки, api.js-клиент, styles.css, навигация) — **стилистика и стек 1:1**, никакого нового тулчейна (bundler — только если roadmap §7 решён иначе).
5. Референс UX: `docs/reference/UI макеты/` + живой экран еды.

## Граница записи
**Только:** `app/delivery/miniapp_api/static/**` (свои новые .jsx/.css модули + регистрация экрана в навигации `app.jsx` — это разделяемый файл фронта: правка минимальная, только добавление своего экрана; конфликт волны разруливает интегратор).
**Запрещено:** весь Python-бэкенд, `openapi.yaml` (нашёл несоответствие — парковка `Q-fe-*`), чужие экраны, `tests/` бэкенда.

## Порядок работы
1. Прочитать вход → выписать сценарии экрана из ТЗ (S-секция) как чеклист.
2. api-клиент: дополнить `api.js` методами своего контекста строго по openapi (пути/поля 1:1).
3. Экран: состояния loading/empty/error (по `ErrorDTO.message` — ru); все мутации — оптимистично или со спиннером, но без потери ввода.
4. Видимость в UI: то, что бэк скрывает, фронт не «дорисовывает» (нет «3 скрытых элемента»); подарки — просто отсутствуют для исключённого.
5. Самопроверка: чеклист сценариев против живого dev-бэка (`python -m app.main`), мобильная ширина (Mini App = телефон), отчёт по build-contract §7.

## Не фантазировать
Дизайн — по образцу экрана еды (цвета/отступы/компоненты переиспользовать из `components-shared.jsx`); новые UX-паттерны, фильтры и фичи сверх ТЗ-сценариев — парковка, не самодеятельность. Тексты — ru.

## DoD
Все S-сценарии ТЗ кликабельны на dev-бэке · ошибки 401/403/404/422 показываются по-человечески · ничего вне границы записи · отчёт + парковка.
