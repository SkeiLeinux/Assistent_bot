## 1. Что это и зачем
- **Проект:** общий бытовой ассистент для пары (Telegram-бот + Mini App). Эволюция существующего и развёрнутого `lifeManager_bot`.
- **Двойная цель:** (основная) пройти полный цикл LLM-ассистированной разработки ради опыта; (желательная) рабочий инструмент для двоих.
- **Метод-эксперимент (пайплайн):** интервью → требования → доменная модель → **ADR** → ТЗ по доменам → субагенты → код. Claude ведёт проект как ведущий; решения по продукту/архитектуре — за стейкхолдерами.

Цена — +0.3–0.8 с на позицию с брендом, принята. (2) **ADR-0018** «Отказоустойчивость LLM-провайдера» (OQ-2=B, OQ-3=ADR): вторичный таргет **`gpt-5.4`** (тот же вендор/ключ/SDK, паритет 92%); рекомендация Claude была Groq `qwen` — **отклонена С.**, и обоснование сильнее исходного: резерв с точностью 76% выдаёт молча неверные КБЖУ, что по принципу «честная ошибка лучше правдоподобной выдумки» хуже отказа, а фактический инцидент 17.07.26 был **модельного**, не вендорского уровня. При внесении решения выявлено следствие общего ключа: **матрица переключения сужена до отказов модельного уровня** — 401/`insufficient_quota`/org-429 резервом не лечатся и идут в алерт, иначе резерв добавляет 20 с перед тем же отказом. Плюс таймаут, ретраи, **startup-guard по `/v1/models`** и суточная проверка (отловили бы 17.07.26 за месяц) и лог usage/латентности/источников (без него второй немой отказ незаметен). **Побочное следствие обоих решений — Groq уходит из кода целиком** (оба таргета ходят по OpenAI-compat; `openai` становится обязательной зависимостью, оговорка про I7 в докстринге снимается). OQ-6 (ветка `unreadable`) решён Claude по best practices: **отдельный массив `unresolved`** в ответе вместо nullable-КБЖУ и нового значения `ProvenanceSource` — контракт `items` не ослабляется ради 8% случаев; сохранение позиции без чисел запрещено (запись с нулями выглядит как данные и портит итоги/цели/дайджест); Катя может переиграть UX-часть. OQ-4: **пороги проверок калибруются на 25 эталонах и сохранённых прогонах ДО написания кода** (пункт 0 в DoD) — 0.20/0.35 были гипотезой, а данные есть. Приёмка — регресс раннера: не хуже baseline (kcal ≤2%: 92%, БЖУ ≤2%: 83%, кДж-конфузий 0) + новая метрика «отказ вместо выдумки» на A-07. **Исполнение — Claude Code, одним заходом вместе с внедрением ADR-0017 §16** (пока прод на qwen через Groq, а раннер меряет `gpt-5.4-mini`, промпт настраивается вслепую).

## 5. Замороженные решения (не пересматривать без явного повода)
- **Вариант C:** дизайн полным пайплайном к чистой target-архитектуре; на коде переиспользуем существующее, новое пишем с нуля.
- **Стиль:** модульный монолит. Микросервисы/брокеры/multitenancy вне рассмотрения (2 пользователя, 1 сервер).
- **UX:** весь интерактивный UI — в Mini App. Бот = точка входа (запуск, `initData`) + push (напоминания, дайджест).
- **Данные:** текущие тестовые данные сносятся, схема строится с нуля (миграций со старого формата нет).
- **Приватность:** принято в **ADR-0001** — унифицированная модель `scope` (`personal|family`) + `hidden_from`; `hidden_from` персистится join-таблицей (под-решение H3). Подарки = `family` + `hidden_from=[одаряемый]`.
- **Финансы MVP:** только импорт Google-таблицы → аналитика (план/факт, иерархия, доходы). Ввод транзакций и автоматизация (ФНС) — North Star. Импорт = **заменяемый anti-corruption layer** (таблицу скоро переработают из-за переезда; домен не зависит от формы таблицы).
- **Аналитика:** on-the-fly, без предрасчёта (объём данных крошечный).
- **Подарки — в MVP** (третий режим приватности проектируется сразу, не ретрофитом).
