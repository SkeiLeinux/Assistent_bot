# Feasibility — техническая осуществимость интеграций North Star

**Дата проверки:** 2026-06-10 (веб-ресёрч; ссылки внизу каждого блока)
**Зачем:** требования этапов E2–E5 опираются только на проверенные пути; «менять доки на этапе реализации» — анти-цель. Каждый вердикт: ✅ путь подтверждён · ⚠️ возможен, нужен gate-тест · ❌ не путь.
**Правило:** перед ТЗ этапа выполняется его **gate-тест** (практическая проверка на своих данных/аккаунтах) — дешёвый эксперимент до строчки кода.

## 1. Huawei Health (тренировки, сон, пульс, шаги, вес) — для E3

| Канал | Вердикт | Суть |
|---|---|---|
| **Privacy-экспорт данных** («Аккаунт → Центр конфиденциальности → Запросить свои данные → Здоровье») | ✅ **рекомендованный путь** | Официальная функция: zip приходит на почту **за минуты** (не дни), внутри JSON + xlsx по папкам (Health detail, Motion path, Sport per minute, SportsHealth), архив под паролем, ссылка живёт 21 день. Формат разбирается сообществом (Hitrava — тренировки; парсеры weight/body-fat). Идеально ложится в наш **ACL-паттерн** (как xlsx бюджета): пользователь раз в N дней запрашивает экспорт → грузит zip в Mini App → импортёр-адаптер. |
| Health Kit (cloud REST API) | ⚠️ запасной | API существует (OAuth, REST), но требует Huawei Developer-аккаунт, заявку на data-scopes и прохождение ревью приложения. Для пет-проекта на двоих — тяжёлая бюрократия с неочевидным одобрением health-скоупов. Рассматривать, только если ручной экспорт надоест. |
| Health Connect (Android) | ❌ для нас | Huawei Health **нативно не пишет** в Health Connect; мосты — сторонний платный Health Sync. Главное: Health Connect — **on-device API**, читать его может только собственное Android-приложение, которого у нас нет и не планируется до E5+. |
| Google Fit REST | ❌ | Новые подключения закрыты с 01.05.2024, полное отключение API — **конец 2026**. Тупиковая ветка, не инвестируем. |

**Gate-тест E3 (30 мин, без кода):** Катя/С. запрашивают экспорт на своих аккаунтах → убедиться, что в zip есть нужные метрики (тренировки с типами, сон, вес, шаги, пульс) и их JSON-структура читаема. Только после этого — ТЗ Health-импортёра.

Ссылки: [экспорт Huawei ID-данных](https://consumer.huawei.com/en/support/content/en-us00746223/) · [структура zip (community)](https://github.com/aricooperdavis/Huawei-TCX-Converter/issues/19) · [Hitrava](https://github.com/CTHRU/Hitrava) · [Health Kit REST](https://developer.huawei.com/consumer/en/doc/HMSCore-References/rest-overview-0000001254420693) · [Health Sync FAQ](https://healthsync.app/f-a-q/) · [Fit migration](https://developer.android.com/health-and-fitness/health-connect/migration/fit)

## 2. Чеки ФНС (item-level траты) — для E2

Предпосылка: покупки в РФ-магазинах (Пятёрочка/Магнит/ВкусВилл в таблице). **Если жирная доля покупок вне РФ — каналы A–C не работают, остаётся D** (вопрос в опроснике Q2).

| Канал | Вердикт | Суть |
|---|---|---|
| **A. proverkacheka.com API** | ⚠️ **первый кандидат**, gate-тест | Неофициальный, но живой и популярный API: `POST /api/v1/check/get` c токеном и `qrraw` (строка из QR) → полный JSON чека с позициями. Бесплатно ~**15 запросов/сутки** — для пары это покрывает обычный ритм покупок; платные тарифы есть. Риски: неофициальность (может умереть/поменять условия), зависимость от базы ФНС. |
| **B. Официальное «Открытое API проверки чека ККТ» (ФНС)** | ⚠️ изучить на gate | ФНС публикует технические условия открытого API проверки чека (kkt-online.nalog.ru). Нужно проверить на gate-тесте: отдаёт ли **позиции** или только валидность чека; условия подключения. Если отдаёт позиции — предпочтительнее A (официальность). |
| C. «Мои чеки онлайн» (lkdr.nalog.ru), неофиц. клиенты | ⚠️ хрупко | Сервис ФНС с электронными чеками; публичного API нет, community-клиенты ломаются при обновлениях ФНС (SMS-auth, капча). Плюс канала: чеки попадают сами (без сканирования QR), если на кассе указывать телефон/почту. Держать как опцию, не как фундамент. |
| **D. Фото чека → vision-LLM (Groq)** | ✅ универсальный fallback | Без внешних API вообще: фото чека в Mini App → vision-разбор на позиции (паттерн уже отработан на еде: analyze → confirm → save). Работает в любой стране и для «мест без чеков» (Катя: ручной ввод). Минусы: точность OCR на мятых чеках → обязательный экран подтверждения (он и так в паттерне). |

**Архитектурное следствие (в ТЗ E2):** канал чека — **заменяемый адаптер** (тот же ACL-паттерн, что Import xlsx): домен принимает нормализованный `ParsedReceipt`, источник (A/B/C/D) подключается/меняется без затрагивания домена. Канал D строится всегда (fallback + не-РФ + без-чековые траты); A или B — по gate-тесту.

**Gate-тест E2 (1 вечер):** зарегистрировать токен proverkacheka → прогнать 10 реальных QR из ваших чеков → оценить полноту позиций; параллельно прочитать ТУ официального API ФНС; 2 фото чеков через Groq vision — оценить качество распознавания.

Ссылки: [proverkacheka API (обзор интегратора)](https://infostart.ru/1c/tools/2173453/) · [proverkacheka](https://proverkacheka.com/) · [Открытое API ККТ — описание](https://kkt-online.nalog.ru/ap-description/) · [ТУ ФНС (PDF)](https://www.nalog.gov.ru/files/kkt/pdf/%D0%A2%D0%B5%D1%85%D0%BD%D0%B8%D1%87%D0%B5%D1%81%D0%BA%D0%B8%D0%B5%20%D1%83%D1%81%D0%BB%D0%BE%D0%B2%D0%B8%D1%8F%20%D0%B8%D1%81%D0%BF%D0%BE%D0%BB%D1%8C%D0%B7%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D1%8F.pdf) · [Мои чеки онлайн](https://lkdr.nalog.ru/) · [опыт клиента nalog.ru](https://leftjoin.ru/all/nalog-ru-client/)

## 3. LLM-бюджет (Groq free tier) — для E2/E4

Лимиты free tier для `llama-4-scout` (примерно, по данным на начало 2026): **~30 RPM / ~1000 запросов в сутки / 6–30k TPM**. Для двоих этого хватает на: разбор еды (текущее, ~10–20 зап/день), чек-vision E2 (~5/день), извлечение анализов E3 (редко), утренний план + вечерний сценарий E4 (~10/день). Запас многократный; binding constraint — RPD, и мы от него далеко. Vision-ограничения уже в ТЗ Nutrition (base64 ≤ 4 МБ, ≤ 5 изображений).

**Правило:** новые LLM-фичи остаются на одном провайдер-агностичном `llm_service` (I7 ТЗ Nutrition) — лимиты/смена провайдера лечатся в одном месте. Платный fallback (или второй ключ) — решение по факту упирания, не заранее.

Ссылки: [Groq rate limits](https://console.groq.com/docs/rate-limits) · [обзор лимитов 2026](https://tokenmix.ai/blog/groq-free-tier-limits-2026)

## 4. Прочее (без веб-ресёрча, инженерная оценка)

| Что | Вердикт | Почему |
|---|---|---|
| QR-скан в Mini App (камера) | ✅ | Telegram WebApp даёт `showScanQrPopup` (нативный сканер) — без своих CV-библиотек; fallback — фото + jsQR. Проверить на gate E2 (5 минут). |
| Состав тела из зала (InBody-распечатка) | ✅ | Фото листка → vision-LLM → структурированные показатели → подтверждение. Тот же паттерн analyze→confirm→save. |
| Анализы (PDF/фото лаборатории) | ✅/⚠️ | Фото/PDF → LLM-извлечение показателей. Технически то же; риск — точность на таблицах лабораторий → обязательное подтверждение + хранение исходника. Gate: 3 реальных бланка. |
| Цикл-аналитика | ✅ | Ручной ввод + календарная математика, интеграций не требует. Чувствительные данные → строго PERSONAL (модель видимости уже умеет). |
| Сон | ✅ через Huawei-экспорт (§1) | Отдельного канала не существует — сон приходит в том же zip. |
| Web-push вне Telegram (E5) | ⚠️ | Для standalone: PWA + Web Push API — стандартно, но это смена канала доставки (Notifications-шов готов к этому by design). Решается в ADR E5. |

## 5. Сводка вердиктов для требований

- **E2 (чеки):** строить можно — канал D гарантирован, A/B по gate-тесту. Лимит 15/день (A) достаточен паре.
- **E3 (Huawei):** строить можно — privacy-экспорт официален и быстр; полуручной ритм (раз в 1–2 недели грузить zip) — цена вопроса, подтвердить у Кати (Q3).
- **E4 (LLM-слой):** в лимитах free tier с запасом.
- **Не закладывать:** Google Fit (умирает), Health Connect (нужен свой Android-app), realtime-интеграцию с Huawei (нет канала без своего приложения/одобренного API).
