# Этап E3 — Здоровье (stage-doc)

**Статус:** каркас этапа. Детальное ТЗ — на входе: Q3 заполнен + gate-тест Huawei-zip + ADR-0008/0009 приняты.
**Драйвер:** Катя (медблок, цикл, витамины, статистика тренировок — «блок важный, идей достаточно»); С. (взвешивание, зал, состав тела, сон — сценарий «идеального дня»).
**Грунт:** North Star backlog (req §8 «Здоровье»), feasibility §1/§4, сырые ответы (Катя Б2-2, С. Б1-3); существующие Nutrition (КБЖУ — остаётся своим контекстом) и Reminders (generic — переиспользуются).

---

## 1. Цель и ценность

Вторая половина «здоровья» (первая — питание, уже в E1): тренировки, вес/состав тела, данные с часов, витамины, медицинские показатели и цикл — в одном месте, со статистикой и подсказками, с приватностью по умолчанию.

## 2. Объём этапа (фичи)

| ID | Фича | Прио | Суть |
|---|---|---|---|
| F3.1 | **Журнал веса/измерений** | must | Утреннее взвешивание за 5 сек (сценарий С.); график динамики; источник — ручной + Huawei-импорт. |
| F3.2 | **Журнал тренировок** | must | Ручной лог: тип (волейбол/бег/вело/зал/др.), длительность, опц. калории/заметка; статистика по типам и периодам (Катя). Источник — ручной + Huawei-импорт. |
| F3.3 | **Huawei-импорт** | must | Privacy-zip → ACL-импортёр: тренировки (типы/калории), сон, шаги, пульс, вес. Идемпотентность по периодам, дубли ручное-vs-импорт — ADR-0008. Ритм: пользователь грузит zip раз в 1–2 недели (подтвердить в Q3). |
| F3.4 | **Витамины** | must | Каталог «что у нас есть» (название, производитель, состав-скоуп, чьё) + расписание приёма → генерирует Reminders (глубокая связь Reminders↔домен — первая, аккуратно через явный интерфейс; до этого Reminders generic). |
| F3.5 | **Медблок: показатели и анализы** | should | Рост/вес/давление и лабораторные показатели; загрузка бланка (фото/PDF) → LLM-извлечение → подтверждение → динамика по показателю. Модель — ADR-0009. Исходник хранится. |
| F3.6 | **Цикл** | should | Ввод цикла + календарная фаза + подсказки к тренировкам по фазе (Катя). Строго `PERSONAL` по умолчанию; что и в каком виде шарится — только явно (Q3). |
| F3.7 | **Состав тела** | could | Фото листка анализатора из зала → vision-извлечение → динамика (С.). |
| F3.8 | Напоминания о врачах | — | Уже покрыто generic Reminders (E1); в E3 — максимум пресет/категория. |

**Вне объёма:** realtime-синк с часами (канала нет — feasibility §1); план тренировок от ИИ (E4-кандидат, упомянут С.); Huawei Health Kit API (запасной путь, только если zip-ритм надоест).

## 3. Доменные дельты (концептуально)

Новый bounded context **Health** (peer к Nutrition; КБЖУ остаётся в Nutrition — границу не размываем):

```mermaid
erDiagram
  USER ||--o{ MEASUREMENT : "PERSONAL"
  USER ||--o{ WORKOUT : "PERSONAL"
  FAMILY ||--o{ SUPPLEMENT : "каталог (FAMILY)"
  SUPPLEMENT ||--o{ SUPPLEMENT_SCHEDULE : "расписание"
  SUPPLEMENT_SCHEDULE }o--|| USER : "чьё"
  USER ||--o{ LABRESULT : "PERSONAL"
  USER ||--o{ CYCLE_ENTRY : "PERSONAL (Катя)"

  MEASUREMENT { string type "weight|height|bp|sleep|steps|hr|bodycomp" numeric value string unit datetime at string source "manual|huawei|vision" }
  WORKOUT { string kind datetime at int duration_min numeric kcal string source }
  SUPPLEMENT { string name string brand string scope_note }
  LABRESULT { string analyte numeric value string unit date taken_at string source_ref }
```

- `Measurement` универсальная vs таблицы по типам — главная развилка ADR-0009 (эскиз выше — вариант «универсальная», не решение).
- **Huawei ACL** (`health/importing/`): zip → парсер JSON-папок → нормализованные Measurement/Workout. Паттерн = Import ACL финансов.
- **Связь с Reminders (F3.4):** Health создаёт/обновляет Reminder'ы расписания витаминов через публичный сервис Reminders (направление `health → reminders` — новое ребро графа! Зафиксировать в ADR-0008/доменной модели и import-linter; альтернатива — композиция в delivery). Это первое осознанное межконтекстное ребро — решать явно, не протаскивать.
- **Видимость:** всё `PERSONAL` по умолчанию; `SUPPLEMENT`-каталог — `FAMILY`; цикл — `PERSONAL` без исключений, шаринг производных (фаза в общий план дня E4) — отдельное явное решение Кати.

## 4. Интеграции (вердикты — feasibility §1/§4)

Huawei privacy-zip ✅ (gate-тест: запросить экспорт на своих аккаунтах, сверить метрики); анализы/состав тела через vision ✅/⚠️ (gate: 3 реальных бланка); Health Connect/Google Fit ❌ не закладываем.

## 5. ADR этапа

ADR-0008 (канал Huawei + дедупликация ручное/импорт + новое ребро health→reminders) · ADR-0009 (модель показателей + хранение исходников).

## 6. NFR-дельты

Меддданные — максимум приватности (PERSONAL, без появления в FAMILY-дайджесте без явного согласия — правка композиции Analytics); файлы-исходники (PDF/фото) — кап диска VPS + чистка; LLM-извлечение всегда через confirm-экран.

## 7. Риски

Ритм ручного zip-импорта надоест → деградация данных (митигация: напоминание-пресет «запроси экспорт», лёгкость загрузки; запасной путь Health Kit API); формат zip может меняться (митигация: ACL + тесты на реальном архиве); чувствительность цикл-данных (митигация: PERSONAL-дефолт + Q3 о границах).

## 8. Вход/выход

**Вход:** Q3 → gate-тесты (zip, бланки) → ADR-0008/0009 → ТЗ (`spec-health.md` + дельта Analytics для новых сфер в обзоре/дайджесте — состав решает Катя в Q3) → волна агентов.
**Выход:** Huawei-импорт — рутина ≤2 нед; вес/тренировки/витамины живут в боте; Катины «важные блоки» закрыты или осознанно перенесены.
