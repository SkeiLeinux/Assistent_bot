**Ответ С.:** E3 первым · **Ответ Кати (2026-06-25):** всё равно (приоритет не важен) · **Согласовано:** E3 первым (голос С., Катя индифферентна)

### В2. [оба] Где вы реально покупаете? (юрисдикция чеков — определяет канал)

- (b) Заметная доля вне РФ → для неё только фото-канал (vision)
- (c) Смешанно, опиши пропорцию: _
**Ответ Кати (2026-06-25):** в основном РФ + всякие подписки (видела текущий мес. блок финансов — ОК). С.: РФ сейчас, переезд 5–6 мес (шапка). → согласовано: РФ-now, проектируем под пост-переезд. **NEW:** «подписки» — учесть как регулярную статью/источник.

### В3. [оба] Сценарий внесения чека — что удобнее как ОСНОВНОЙ жест?
- (a) Отсканировать QR сразу на кассе/дома (10 сек)
- (b) Фоткать чеки пачкой и разбирать раз в неделю
- (c) Указывать телефон/почту на кассе → чеки сами падают в lkdr → периодическая синхронизация (хрупкий канал, см. feasibility)
**Ответ С.:** оба жеста (шапка) · **Ответ Кати (2026-06-25):** а + б (QR сразу И пачкой) · **Согласовано:** оба жеста

### В4. [оба] Гранулярность учёта: чек целиком на категорию или разбивка по позициям?
- (a) Чек целиком → одна транзакция («Пятёрочка → Едовое/Пятёрочка», как сейчас в таблице) — просто, быстро
- (b) По позициям с авто-категоризацией — точнее («сладости» отдельно), но дороже в подтверждении
- (c) Гибрид: по умолчанию целиком, «разобрать по позициям» — опция для интересных чеков
**Ответ Кати (2026-06-25):** (б) по позициям с авто-категоризацией + постоянная ручная корректировка; позже перевод в авто-сбор «когда модель обучится и выявим категории». ⚠️ Расхождение с гибридом С. (c): позиции хранятся всегда у обоих, развилка — **дефолт** (целиком vs по позициям). НЕ согласовано — решение С.
