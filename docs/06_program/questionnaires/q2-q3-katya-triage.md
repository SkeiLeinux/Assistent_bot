## 4. Решения, нужные от С. (сведено)

### 4.1. Пульс и зоны (q3 В2/В3) — главный конфликт
- Катя просит: средний пульс, мин/макс, **разбивку по зонам**. С. и #16: пульс/зоны вне scope (только тренировки/сон/шаги сводно).
- **Факт со скрина Кати:** на экране тренировки прямо напечатаны **средний пульс (101), максимум (134) и минуты по зонам** (Экстрим/Анаэробная/Аэробная/Сжигание жира/Разминка). Это **дешёвые для vision** числа — не «глубокий ряд».
- **Не извлекается со скрина:** непрерывная кривая пульса (график) и **явный минимум** (как отдельное число его на экране нет, только нижняя граница оси).
- **Рекомендация:** включить в scope **сводный пульс (средний/макс) + минуты по зонам** (берётся тем же скрином, что калории/длительность), а **кривую и явный минимум — не брать**. Это закрывает ~80% запроса Кати почти без удорожания канала.
- **Решение С.:** [ ] включить сводный пульс+зоны · [ ] остаться без пульса (#16 как есть) · [ ] иное.

### 4.2. Read-only приватность (q3 В6/В8) — возможный примитив kernel
- Катя: готова делиться **всем** (вкл. цикл), единственное жёсткое — **партнёр видит, но не редактирует**.
- Текущая модель приватности (`scope` personal/family + `hidden_from`) управляет **видимостью**, но не **правом записи**: family-сущности редактируемы обоими. «Видит, но не редактирует» — это **новый примитив** (владелец пишет, семья читает).
- **Решение С.:** нужен ли owner-write / family-read как общий механизм (ADR-кандидат, влияет на kernel) — или достаточно частного правила для health-доменов в E3? [ ] общий примитив (ADR) · [ ] частное правило E3 · [ ] иное.

### 4.3. Цикл-сигналы в общий план дня (q3 В6 → E4)
- Катя не против, чтобы производное от цикла (фаза/настроение) питало **твои** напоминания («покорми вкусняшками»). Финальное — твоё (она пометила «вопрос к нему»).
- **Решение С.:** [ ] да, производные цикла (без деталей) → мои напоминания/план дня E4 · [ ] нет · [ ] решить на входе E4.

### 4.4. Рост скоупа E3 (q3 В9, В4, В10)
