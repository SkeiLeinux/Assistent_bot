# Этап E5 — Standalone-приложение (stage-doc)

**Статус:** каркас этапа. Запускается **по триггеру** ADR-0005 (реальные данные/рост/мультипроцесс/standalone-желание), может идти параллельно E4. Шов под него удерживается с E1 (ADR-0004: Telegram заперт в `kernel.auth` + `delivery` + `notifications`).
**Грунт:** req §5/§8 («мягкое ограничение — чистая граница API»), NFR «не оверинженерим заранее».

---

## 1. Цель и ценность

Жизнь вне Telegram: тот же бэкенд, фронт как самостоятельное web-приложение (PWA на телефоне), своя аутентификация. Telegram остаётся каналом push и запасным входом. Ценность: независимость от платформы (лимиты Mini App, блокировки, UX-ограничения WebView).

## 2. Объём этапа

| ID | Фича | Прио | Суть |
|---|---|---|---|
| F5.1 | **Своя аутентификация** | must | Замена `initData`-резолва на собственный auth-слой (выбор механизма — ADR-0010: пароль+TOTP / magic-link / OAuth). Whitelist-философия сохраняется (двое). `current_viewer`-контракт не меняется — домены не замечают. |
| F5.2 | **PWA-фронт** | must | Тот же SPA, hosting за пределами Mini App (тот же VPS + nginx/https), манифест+SW, установка на телефон. Сборка фронта — решение волны C (roadmap §7) наследуется. |
| F5.3 | **Web-push** | must | Доставка вне Telegram: Notifications получает второй транспорт (Web Push API). Политика (ретрай/алерт) переиспользуется; выбор канала per-user. |
| F5.4 | **PostgreSQL** | should | Триггер ADR-0005 наступил по определению этапа; миграция SQLite→Postgres по подготовленной портируемости (БД-специфика изолирована с E1). |
| F5.5 | Доступ извне | must | HTTPS, домен, секреты, бэкапы — инфраструктурный минимум (сейчас всё за Telegram-периметром). |

**Вне объёма:** нативные приложения; мультитенантность/регистрация посторонних (двое — всё ещё аксиома); отказ от Telegram (остаётся каналом).

## 3. Архитектурные дельты

- **`kernel.auth`:** второй резолвер viewer'а рядом с `initData` (стратегия по заголовку); инварианты I1–I11 без изменений.
- **`notifications`:** транспорт-абстракция (Telegram Bot / Web Push) — интерфейс `deliver` уже транспорт-нейтрален по форме.
- **`delivery`:** статика наружу, CORS/CSRF-модель, rate-limit на внешней границе (впервые появляется недоверенная сеть!). Это главный новый класс рисков этапа — безопасность внешнего периметра при «домашнем» проекте.
- **БД:** alembic тот же; типы/JSON уже портируемы (ADR-0005 готовил).

## 4. ADR этапа

ADR-0010 (auth-механизм + модель угроз внешнего периметра). Возможен **ADR-0015** (web-push транспорт vs упрощения), если F5.3 окажется тяжелее ожиданий. _(0013 занят nutrition-retrieval; 0014 — E4-связки.)_

## 5. Риски

Безопасность внешнего API (раньше всё пряталось за Telegram+whitelist) — главный; бюджет времени на «инфра-возню» (https/домен/бэкапы) часто недооценивается; PWA-push на iOS капризен (если у кого-то iPhone — проверить на gate-тесте этапа).

## 6. Вход/выход

**Вход:** триггер ADR-0005 зафиксирован · ADR-0010 принят · gate-тест web-push на целевых телефонах.
**Выход:** оба пользуются вне Telegram ≥2 недель; push приходят; Telegram-канал жив как запасной.
