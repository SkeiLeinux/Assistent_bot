## 1. Вопрос

Сценарий (North Star «vision→поиск»): для брендового продукта вернуть **реальный КБЖУ с упаковки**, а не усреднённую прикидку модели. Три кейса: (1) текст «200гр молоко Домик в деревне 3.2%»; (2) фото этикетки + порция; (3) фото продукта/тарелки.

**Ключевая техническая истина:** LLM **сам в интернет не ходит**. Retrieval — отдельная способность: либо встроена у провайдера (агентный веб-поиск с цитатами), либо реализуется своим tool-loop с вызовом внешнего API. Текущая `llama-4-scout` искать не умеет; **смена модели поиск не добавляет**. Значит, нужен отдельный слой источников за единым контрактом (как ACL финансов, ADR-0002).

## 2. Источники структурированных данных о составе

| Источник | Доступ | За | Против |
|---|---|---|---|
| **Open Food Facts (OFF)** | Free, **без ключа** (обязателен кастомный `User-Agent`); barcode + полнотекст | Бренды + штрихкоды; КБЖУ на 100 г; 1.3M+ товаров; открытая база | RU-хвост покрыт **частично** → нужна лестница фолбэков |
| Nutritionix | Free 1000/мес, **ключ**; NL-эндпоинт («200g milk») | Хорош для generic/англоязычных | Слаб по RU-брендам; USDA-ориентирован |
| USDA FoodData Central | Free, ключ | Точные generic-данные | Только англоязычные/USDA-продукты; RU-бренды отсутствуют |
| Web-only (без структуры) | — | Максимум охвата | Хрупко, без схемы, риск галлюцинаций чисел |

**Вывод:** OFF — первичный структурный источник (бесплатно, без ключа, штрихкоды + бренды). Nutritionix/USDA — опциональная generic-ступень позже.

## 3. Веб-фолбэк (когда структурной базы не хватило)

В 2026 бесплатные generic web-search API почти исчезли: **Tavily — платный**, **Brave** убрал вечный free-tier. Доступный бесплатный путь — **Groq Compound** (агентный веб-поиск, встроен в Groq-использование, поиск на Tavily, отдаёт цитаты). Это закрывает драйвер «бесплатный стек» (NFR §5), не вводя новой обязательной платной интеграции. Vision у Compound на 2026-06-13 **не подтверждён** → для фото остаются 2 ступени (Scout-извлечение → Compound/текст-поиск).

## 4. Отклонённые варианты модели

- **Сменить LLM на DeepSeek — отвергнуто.** Не даёт retrieval (поиск — отдельная способность, не свойство модели); API **не бесплатен**; встроенного веб-поиска нет; vision не закрывает retrieval. Смена модели проблему не решает.
- **«Пусть модель гуглит» (наивно) — отвергнуто.** Галлюцинации чисел в health-инструменте; цена тихой ошибки высока (ср. fail-loud ADR-0002).

## 5. Ограничения и латентность

- **Лимиты:** OFF ~10/мин (поиск), ~15/мин (товар); Groq — free tier. На 2 пользователей запас есть.
- **Латентность:** 1–2 LLM + 1–2 сетевых = несколько секунд; гасится **кэшем находок в `SharedFood`** (каталог = самонаполняющийся кэш) и таймаутами на ступень.
- **RU-покрытие OFF** частично → лестница фолбэков обязательна; авто-кэш постепенно закрывает длинный хвост.

## 6. Вывод (→ ADR-0013)

Свой **резолвер с детерминированной лестницей** источников за портом `ProductResolver`:
`label-short-circuit → (barcode fast-follow) → OFF полнотекст → (веб через Compound — этап R2) → estimate (оценка модели)`.
Провенанс на каждой позиции (`label`/`off`/`web`/`estimate`); найденное (≠`estimate`) кэшируется в `SharedFood` при сохранении записи. LLM остаётся Groq/Llama-4-Scout (модель-агностичность контракта `NutritionLLM`). Barcode — fast-follow; Nutritionix/USDA — опционально позже.

**Gate-тест RU-покрытия OFF** пройден (С., 2026-06-13) — покрытие основных продуктов достаточное для запуска R1.

## 7. Источники (внешние)

- Open Food Facts API — https://world.openfoodfacts.org/data (полнотекст `cgi/search.pl`, товар `api/v2/product/{barcode}`), требование `User-Agent`.
- Groq Compound (агентный веб-поиск, Tavily, цитаты) — документация Groq.
- Nutritionix Natural Language endpoint; USDA FoodData Central API.
