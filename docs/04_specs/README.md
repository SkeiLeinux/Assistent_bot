# ТЗ по доменам — индекс и трекер фазы

**SSOT по статусам ТЗ.** Фаза `04_specs/` переводит концептуальную доменную модель (`02_domain/DOMAIN_MODEL.md`) и принятые ADR (`03_architecture/adr/`) в реализуемые ТЗ по каждому bounded context — один файл `spec-<домен>.md` на контекст. ТЗ — последний артефакт перед раздачей субагентам/кодом.

**Опирается на:** `01_requirements/MVP_Requirements.md` (SSOT по объёму), `02_domain/DOMAIN_MODEL.md` (границы и граф зависимостей), `03_architecture/adr/` (архитектурные решения). При расхождениях источник истины — эти документы, **не** история чата и **не** память.

## Шаблон полного ТЗ (канонические разделы)

Каждый `spec-<домен>.md` следует единой структуре (уровень детализации — «полное ТЗ», утверждён 2026-06-06):

1. **Шапка** — версия, статус, дата, на что опирается, какой контекст DOMAIN_MODEL закрывает.
2. **Назначение и границы контекста** — ответственность; что входит / НЕ входит; маппинг на код (reuse / new).
3. **Глоссарий контекста** (если нужен сверх общего).
4. **Доменная модель** — сущности + атрибуты (поле · тип · NULL? · описание · инвариант), отношения.
5. **ERD** — `mermaid erDiagram`.
6. **Инварианты и бизнес-правила** — нумерованные, проверяемые.
7. **Модель видимости в контексте** — как применяется `Shareable`/`visible_to` (для kernel — определение механизма).
8. **Состояния и переходы (FSM)** — где есть.
9. **Прикладные сценарии** — use-cases: actor → шаги → исход.
10. **REST-контракт** — эндпоинты (метод · путь · auth · запрос · ответ · коды ошибок) + DTO-схемы.
11. **Аутентификация и авторизация** — для kernel разворачивается; прочие контексты ссылаются на kernel.
12. **Структура пакета и публичная граница** — из ADR-0004 (что экспортируется, что нельзя импортировать).
13. **Edge-cases и обработка ошибок.**
14. **Нефункциональные аспекты** — горячий путь, локализация, standalone-шов (кратко, ссылка на req §5).
15. **Критерии приёмки** — проверяемые, включая тест-инварианты.
16. **Открытые вопросы** — что осталось решить (продукт / архитектура), с адресатом и рекомендацией.
17. **История изменений.**

Эталон структуры — первый принятый ТЗ (`spec-identity-sharing.md`), по аналогии с тем, как формат ADR задан принятыми ADR.
