## 4. Smoke — 5 минут, руками

> **С 2026-08-10 этот чек-лист можно прогнать скриптом** — те же кейсы (та самая корейка с парой
> кДж/ккал — S-01, текст — S-04, кап — S-05) через HTTP задеплоенного инстанса, плюс проверка
> версии через `GET /api/v1/health`, которой руками не сделать:
>
> ```bash
> python scripts/smoke.py --base-url https://bot.lifemanageronline.ru --user-id 548089936
> ```
>
> **Токен берётся из `SMOKE_BOT_TOKEN` в локальном `.env`** (поле объявлено в `config.py`, тип
> `SecretStr`). Отдельное поле — не удобство: в `BOT_TOKEN` на ноутбуке лежит ТЕСТОВЫЙ бот (на нём
> отлаживается UI мини-апы), и подпись им даёт 401 на всех кейсах при живом `/health`. Просто
> дописать переменную в `.env` было нельзя — `extra=forbid` уронил бы процесс на импорте, тот же
> механизм, что дал краш-луп 02.08. Второе расхождение локальной копии: `WEBAPP_URL` указывает на
> мёртвый quick-туннель `*.trycloudflare.com`, поэтому адрес задан явно.
>
> **Ожидаемый коммит по умолчанию — локальный HEAD.** Если прод намеренно отстаёт (проверяем
> предыдущую выкатку), сверяйся явно: `--expect-commit <sha прода>`.
>
> Задание — `code-task-smoke-2026-08-10.md`, отчёт — `smoke-2026-08-10.md`.
>
> **Обязательным шагом выкатки смоук НЕ является** (решение С., 2026-08-10): чек-лист ниже
> остаётся основным, скрипт — инструмент, а не гейт. Он покрывает первые три пункта; четвёртый
> (скорость на тарелке) в любом случае остаётся глазами.
>

> пользователя не заводим: под существующим пользователем смоук не пишет в БД ни строки, а вот
> новый id при первом же заходе создаёт запись `User` (auto-provision, spec-identity §8.5) — то
> есть «чище» оказался как раз реальный. Оба свойства под тестами
> (`tests/test_smoke_cases.py`), а не под этим абзацем.
