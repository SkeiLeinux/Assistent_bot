## 2. `.env` — блокирующий шаг (делать ДО `git pull`)

`Settings` объявлен с `extra=forbid`. Любой ключ в `.env`, которому нет поля в `app/config.py`,
роняет процесс на импорте с `ValidationError: Extra inputs are not permitted` — **до** запуска бота,
логов домена и алерта админу. Волна 1 удалила четыре поля Groq, значит текущий прод-`.env` несовместим
с новым кодом по построению.

**Удалить (полей больше нет):**

```
GROQ_API_KEY
GROQ_MODEL
GROQ_MAX_IMAGES
GROQ_REASONING_EFFORT
```

**Добавить (единственный обязательный новый ключ):**

```
LLM_API_KEY=sk-...        # ключ OpenAI; НЕ OPENAI_API_KEY — то поле только для eval-раннера
```

**Ничего не добавлять сверх этого.** Остальные новые поля (`LLM_BASE_URL`, `LLM_VISION_MODEL`,
`LLM_TEXT_MODEL`, `LLM_MAX_IMAGES`, `LLM_BATCH_CONCURRENCY`, `LLM_REASONING_EFFORT`, `LLM_TEMPERATURE`,
`LLM_MAX_TOKENS_PARAM`, `LLM_TIMEOUT_S`, `LLM_RETRY_429`, `LLM_OUTPUT_TOKENS_*`, `CHECK_*`,
`RESOLVER_VERIFY_LABEL`, `RESOLVER_DISAGREE_PCT`) имеют дефолты, откалиброванные на 25 эталонах
(`llm-checks-calibration-2026-07-27.md`). Переопределять их «на глаз» — значит ломать калибровку.

**Заодно сверить имена старых ключей** (они не менялись, но `extra=forbid` не прощает):
`BOT_TOKEN`, `DATABASE_URL`, `ALLOWED_USER_IDS_RAW` (именно с суффиксом `_RAW`), `ADMIN_TELEGRAM_ID`,
`WEBAPP_URL`, `WEBAPP_HOST`, `WEBAPP_PORT`.

## 6. Smoke — обязателен, лог его не заменяет

Инцидент 17.07.26 был немым: модель сняли, а пользователь видел «сервис временно недоступен».
Здесь тот же класс отказа проверяется руками.

- [ ] **Текст:** в дневнике ввести «200 г гречки» → пришли КБЖУ, не ошибка.
- [ ] **Фото этикетки:** снять любой товар с таблицей питательности → числа совпали с упаковкой.
      Это же проверяет `readout=label` и новый единый промпт.
- [ ] **Фото блюда:** тарелка с 3–4 позициями → позиции разложены, вес спрашивается у пользователя,
      `portion_g` модель не выдумывает.
- [ ] **Ошибка ключа читаема:** если ключ неверный — в мини-апе ожидается `503` с текстом,
      а не «кривой JSON» и не тишина.
- [ ] Экран подтверждения (`analyze → confirm → save`) на месте: автосохранение по фото недопустимо
      (остаточная ошибка «верное имя, неверные числа» ~8% этикеток, ADR-0017).

## 8. Что после этого деплоя ожидаемо НЕ работает

Чтобы не диагностировать это как баги релиза.

1. **Ступень OFF в лестнице и вредна.** *(обновлено 2026-08-03: формулировка «мертва» неверна — она
   отвечает; замер `off-value-2026-08-03.md` показал худшее: она отвечает **не тем товаром**. Принят
   вариант D, поисковый вызов удаляется. Действие то же — пустой `network_sources`, — но основание
   сильнее: не «бесполезное ожидание», а 11 грубых подмен из 25.)*

   Исходная формулировка: `cgi/search.pl` отдаёт 503 с 2026-07-28
   (`off-source-probe-2026-07-28.md`), а `build_resolver()` его подключает. Каждая позиция без этикетки
   и каждая брендовая с этикеткой ждёт `off_timeout_s = 2.5 с` впустую, потом падает в `estimate`.
   Тарелка из 4 позиций — до 10 с ожидания в никуда при бюджете 12 с. **Самая дешёвая правка проекта:
   пустой `network_sources` в `resolve/__init__.py`** до миграции на `search-a-licious` (блок 7).
2. **Сверка label-preferred выключена.** `match_confidence()` всегда `None` — сознательное безопасное
   состояние после незакрытого гейта ADR-0019. `RESOLVER_VERIFY_LABEL` пока не влияет ни на что,
   кроме лишнего похода в мёртвый OFF из п.1.
3. **Блок 11 (ADR-0018) не отгружен:** таймаута на LLM-вызов нет, `LLM_TIMEOUT_S` и `LLM_RETRY_429`
   лежат в конфиге неиспользованными, вторичный таргет `gpt-5.4` не подключён, суточной проверки
   доступности модели нет. Следующее снятие модели снова будет немым.
4. **Блок 15 не отгружен:** `api/routes.py` режет ввод хардкодом `[:5]` в двух местах, фронтовый кап
   тоже 5 → батчи из блока 6 через REST недостижимы и лежат мёртвыми.
5. **`unresolved` не показывается.** Бэкенд честно возвращает 200 с массивом отказов (ТЗ §6.6),
   фронт про него не знает: при `readout=unreadable` пользователь увидит просто меньше позиций
   без объяснения.
6. **barcode не реализован** (fast-follow ADR-0019 §2.2).

Пункты 1 и 3 — кандидаты в ближайший мелкий инкремент; п. 6 и миграция OFF ждут решения по
развилке ADR-0019 §9 (рекомендация — вариант D).
