**Дата:** 2026-06-10 · **Статус:** действует с волны A
**Закрывает:** GAP-1/2/3/5 аудита (`chain-audit.md` §4). Операционный слой между ТЗ (`04_specs/`) и кодом: roadmap §5 говорит «кто строит что», этот файл — «как строить параллельно и не столкнуться».
**Цель-метрика (С.):** запустить волну агентов, вернуться через полдня — каждый агент либо закрыл свой DoD, либо припарковал вопросы; ничего не выдумано, общие файлы не тронуты.
**Брифы агентов:** `.claude/agents/*.md` (конфиг, не docs — CLAUDE §4). Брифы ссылаются сюда; при расхождении этот файл главнее.

> **Статус (2026-06-20):** волны A/B/C исполнены, MVP отгружен на VPS и тестируется; документ — переиспользуемый процесс для будущих волн (E2+).

## 2. Двухфазный цикл агента (обязателен)

1. **Прочитать вход** (список в брифе; всегда: своё ТЗ целиком + kernel ТЗ §3.5/§5/§7/§10 + roadmap §2/§3 + этот файл).
2. **Фаза 1 — тесты:** написать скелеты приёмочных тестов по **A-критериям своего ТЗ** (каждый A-пункт ⇒ ≥1 тест; видимость — через `tests/shareable_harness.py`). Тесты — контракт DoD, пишутся ДО кода.
3. **Фаза 2 — код:** реализация до зелёного. Никаких живых внешних вызовов в тестах (LLM/Telegram — моки/фейки).
4. **Самопроверка DoD** (§5) → **отчёт** (§7).

## 3. Границы записи (ownership) — железно

Агент пишет **только** в свои пути. Всё прочее — read-only. Нарушение границы = провал приёмки независимо от качества кода.

| Агент | Запись разрешена |
|---|---|
| finance-agent | `app/contexts/finance/**`, `tests/test_finance*.py` |
| nutrition-agent | `app/contexts/nutrition/**`, `tests/test_nutrition*.py`; **минус-права:** удалить транзит-сырьё еды после переноса (`app/services/{food_service,llm_service}.py`, `app/repositories/{food_repository,shared_food_repository}.py`) |
| reminders-agent | `app/contexts/reminders/**`, `tests/test_reminders*.py` |
| analytics-agent | `app/analytics/**`, `tests/test_analytics*.py` |
| delivery-agent | `app/notifications/**`, `app/delivery/bot/**`, `tests/test_notifications*.py`, `tests/test_delivery*.py` |
| frontend-agent (волна C, per-экран) | `app/delivery/miniapp_api/static/**` (свои модули + минимальная регистрация экрана в `app.jsx`) |
| spec-writer-agent (вход этапов E2+) | только свой новый `docs/04_specs/spec-<x>.md` (черновик) |
| reviewer-agent | **ничего** (read-only) + свой отчёт в `docs/05_implementation/reviews/` |
| integrator | общие файлы (§6) |

**Общие файлы — не трогает никто, кроме интегратора:**
`alembic/**` (⚠️ multi-head уже стрелял в S0 — прецедент), `app/main.py`, `app/delivery/miniapp_api/**` кроме `static/` (монтаж REST; `static/` — frontend-агенты волны C), `app/kernel/**`, `app/db/**`, `pyproject.toml`, `requirements.txt`, `tests/conftest.py`, `tests/shareable_harness.py`, `.env`, `app/config.py`, `__init__.py` транзитных пакетов.

**Отдельно про миграции:** агенты пишут **только модели**. `alembic revision` не выполняет никто, кроме интегратора — одна autogenerate-миграция на волну, после слияния всех моделей, с проверкой единственной головы.

**Зависимости:** новые пакеты в `requirements.txt` добавляет интегратор на старте волны по заявкам брифов (волна A: `openpyxl` для finance). Агент сам не ставит ничего.

## 4. Парковка вопросов (вместо выдумывания)

Принцип: **локальные технические мелочи** (имя приватной функции, разбиение на модули) агент решает сам и фиксирует в отчёте. **Всё, что является контрактом** (REST/DTO, схема БД, семантика инварианта, поведение видимое пользователю) и не задано ТЗ однозначно, — **не решается самовольно**: вопрос паркуется, пункт откладывается, работа продолжается по остальным.

Файл: `docs/05_implementation/questions/<контекст>.md`, формат записи:

```
## Q-<ctx>-N: <тема>
- Где: <ТЗ §, цитата>
- Проблема: <что неоднозначно>
- Варианты: <2–3 с trade-off>
- Обход в коде: <если временно реализован — что и где, иначе «не реализовано»>
```

Известные решённые точки аудита (chain-audit §3) считать частью ТЗ после их влития; до влития — это и есть предусловия волны (§1).

## 5. DoD агента (самопроверка перед отчётом)

```
python -m pytest tests/test_<свои>*.py -q     # все зелёные
lint-imports                                   # контракт не нарушен
python -m pytest -q                            # полный сьют не сломан
```
- Каждый A-критерий своего ТЗ покрыт тестом (маппинг A→тест — в отчёте).
- `git status`: изменения только в своих путях (§3).
- Никаких новых зависимостей, миграций, правок общих файлов.
- Парковка (§4) актуальна.

---

## 6. Интеграционный шаг волны (интегратор: С. или integrator-agent)

Выполняется после того, как все агенты волны отчитались.

1. **Ревью границ:** `git diff --stat` — изменения каждого агента только в его путях.
2. **Линтер достроить** (волна A → перед волной B), в `pyproject.toml`:
   - forbidden: `app.analytics` → `app.contexts.finance.{models,repositories,services,api,importing}` и `app.contexts.nutrition.{models,repositories,services,api}` (аналог существующего lists-контракта);
   - forbidden: `app.analytics` → `app.contexts.reminders`;
   - forbidden: `app.contexts.finance.importing` не импортируется ниоткуда, кроме `app.contexts.finance`.
3. **Зависимости волны** в `requirements.txt` + установка в venv.
4. **Единая миграция волны:** `alembic revision --autogenerate -m "S<n> wave <X>"` → глазами проверить diff → `alembic upgrade head` → `alembic heads` = ровно одна.
5. **Монтаж:** REST-роуты контекстов в `app/delivery/miniapp_api/`; (волна B) регистрация job `reminder_poll` + `digest` в `app/main.py`; удаление отработавшего транзита (`app/delivery/miniapp_api/api.py` старой еды и т.п.).
6. **Полный прогон:** `python -m pytest -q` + `lint-imports` + smoke `python -m app.main` (boot: миграции → polling → web).
7. **Передача reviewer-agent** → чеклист A-критериев волны → вердикт С.
8. Разбор парковок (`questions/*.md`) на чек-поинте; коммит волны — за С.

## 7. Отчёт агента (формат, кладётся в конец сессии агента)

```
## Отчёт <agent> — волна <X>, <дата>
- Сделано: <1–5 строк>
- Маппинг A-критерии → тесты: A1→test_..., A2→...
- DoD: pytest <свои> N passed · lint-imports OK · полный сьют OK
- Парковка: Q-<ctx>-1..N / пусто
- Локальные решения (не контрактные): <список или пусто>
- Границы: подтверждаю — записи только в своих путях
```
