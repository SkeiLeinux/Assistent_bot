## 2. Поток 1 — Баги в Code (fix-лист, сейчас)

> Одна ветка, тесты на каждый, миграций не требуется. Пути/строки — ориентир (код мог сместиться), проверять при заходе.

**B1 (#1) — Mini App: ack повторяющегося напоминания висит вечно.**
Симптом: тап ✓ на recurring → бесконечная загрузка, не завершается. Корень: фронт ждёт, что карточка уйдёт из «Активные», но по ТЗ Reminders ack повторяющегося — no-op для расписания (`reminder_service.ack` пишет только `last_fired_at`, статус остаётся ACTIVE). Спиннер ждёт перехода, которого нет.
**Форк C → решено: «отметить этот раз и повторить».** Бэкенд уже так и делает (статус ACTIVE), спек-правки нет. Фикс чисто фронтовый (`reminders.jsx`): обработать ответ ack для recurring — снять спиннер, показать «отмечено на этот раз», карточку оставить активной (повторится в следующий цикл). Журнал срабатываний не вводим.
Тест: ack recurring → промис резолвится, спиннер снят, элемент остаётся ACTIVE.

**B2 (#11) — Bot push: инлайн-кнопки не убираются, жмутся повторно.**
Корень (подтверждён): `app/delivery/bot/setup.py` (`on_callback`) вызывает `query.answer()`, но **не** редактирует сообщение — нет `edit_message_reply_markup(None)`. Кнопки живут вечно, callback не идемпотентен.
Фикс: после обработки ack/snooze — убрать/перерисовать клавиатуру и заменить на статус-строку. Для recurring (форк C): «✅ Отмечено, повторится …»; для разового: «✅ Выполнено» / «⏰ Отложено до …». Сделать callback идемпотентным (повторный тап по обработанному → `answer` без эффекта).
Тест: повторный callback по обработанному не меняет состояние; разметка снята.

**B3 (#13b) — Finance: шапка План/факт «наехала».**
Корень: `finance.jsx` `.fin-total__*` (grid 1fr/1fr/1fr, без `overflow`/`min-width`/`word-break`). На узких экранах и со знаком `−`/`+` колонки плывут, подписи наезжают.
Фикс: CSS — нумерация без переноса (`white-space:nowrap`, `tnum`), `min-width:0` на ячейке, ужать шрифт значения на малых ширинах; проверить на 360–380px.
Тест: визуальный (скрин до/после на узкой ширине).

**B4 (#15a) — Nutrition: кДж попадает в ккал.**
Корень: промпт `llm_service.py` уже различает кДж/ккал, но рантайм-валидации нет → модель иногда ошибается; OFF-конверсия (`/4.184`) корректна, но без bounds-check.
Фикс: детерминированный guard после извлечения — сверка ккал с макросами (≈ 4Б+4У+9Ж на 100 г); если расхождение ≈ ×4.18 — это кДж, делить на 4.184; плюс верхняя планка правдоподобия (ккал/100г). Лог провенанса коррекции.
Тест: вход «496 на 100 г» при макросах на ~119 ккал → нормализуется к ~119.

**B5 (#7) — Nutrition: мультивыбор фото (мелкий).**
Бэк уже принимает `images[≤5]` (spec-nutrition v0.2.1, в проде). Гэп только во фронте: `<input type="file">` без `multiple` в фото-режиме дневника.
Фикс: добавить `multiple`, собрать ≤5 в один вызов `/foods/analyze`. Проверить лимит и UX превью.

**B6 (X2) — флапающие тесты nutrition.**
6 падений в `test_nutrition.py` (`date.today()` против UTC-хранения). Чинить на детерминированную дату/таймзону (инъекция `now`/freeze). Закрыть до того, как зелёный сьют станет гейтом приёмки.

**V1 (#14b) — наложение полей Срок/Приоритет.** С. говорит, уже поправлено. Не в фикс-лист: на заходе сверить с кодом, если правка на месте — закрыть записью.
