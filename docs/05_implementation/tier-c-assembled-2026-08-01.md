## 2. Найденный дефект: знаменатель C6

**Проценты расхождения веса не сошлись ни у одного набора.** Разбор показал, что ошибка
в коде, а не в документе: `c_weight_mismatch()` (мой же, из блока 1) брал знаменателем
Σ граммовок, тогда как ТЗ контракта §6.4 задаёт **заявленный вес**:

```
C6 = |Σ portion_g_i − weight_g| / weight_g > 0.30
```

Цена ошибки — ровно один набор, и именно тот, который обязан работать:

| Набор | знаменатель Σ | знаменатель `weight_g` (ТЗ) |
|---|---|---|
| **C-05** (положительный контроль) | 150/500 = **30.0%** → `> 0.30` **False** | 150/350 = **42.9%** → **True** |

То есть C6+ не сработал бы, а `expect_weight_mismatch: true` в манифесте выглядел бы
выполненным требованием. Ни один из 17 негативных контролей этого не поймал: синтетика
стояла далеко от границы и срабатывала при обеих формулах.

**Что из этого следует для метода.** Негативный контроль отвечает на вопрос «метрика
вообще шевелится?» — и он на него ответил честно. Вопрос «шевелится ли она в том месте?»
он не закрывает; это закрывает только сверка с источником. Здесь источником оказался
пересчёт процентов из §3C.2 — то есть ровно то независимое опровержение, которого
требует `nutrition-wave-plan.md` §5.

Исправлено, добавлен пин формулы (`test_c6_denominator_is_declared_weight_not_sum`) с
обоими зеркальными случаями: где Σ-знаменатель промолчал бы и где сработал бы лишний раз.
Мутант 17 при исправлении покраснел (его `declared` давал 28.6% по верной формуле) —
значение сдвинуто так, чтобы порог действительно пересекался.

Спецификацию править не пришлось: ТЗ §6.4 и §3C.2 были верны, расходился с ними код.
Для блока 5 (`checks.py`) это уже зафиксировано пином.

## 3. Изменения схемы

**Добавлено обязательное `text_name`** у ингредиента набора C. §3C.2 п.3 требовал явных
формулировок для `dish_text` («макароны сухие»), но требование жило заметкой в тексте, а
состав строился бы из имён с этикеток: `Макароны "Спиральки-экспресс", группа А высший
сорт` не сообщает, что продукт сухой, и модель по умолчанию отдаст `per100g` варёных
(~130 против 342) — метрика C9 записала бы верное поведение как промах втрое. Теперь поле
обязательно и проверяется валидатором.

**Снято исключение `_quarantine/**`** из проверки файлов-сирот. §3D.5 п.2 оговаривал его
«до заведения C-04»; оба кадра теперь адресуются из `extra_images`, то есть перестали
быть вне зачёта. Держать исключение дальше значило бы разрешить копить там что угодно.

**Способность падать проверена четырьмя намеренными сломами реального манифеста:**

| Слом | Кто поймал |
|---|---|
| C-05: `declared_weight_g` 350 → 500 (расхождение убрано) | `test_tier_c_weight_controls_are_meaningful` |
| C-04: граммовки скопированы у C-03 | `test_c_links_real` (эталон уехал) |
| C-04 скопирован целиком, вместе с `expected_total` | `test_tier_c_sets_are_separable` — `(('C-03','C-04'), 0.0)` |
| A-16: эталон правлен 210.9 → 250 | `test_atwater_real` + `test_c_links_real` (истина трёх наборов уехала) |

Третий слом заведён специально: второй поймала связность C→A, а не сама разделимость,
поэтому набор был сделан внутренне согласованным — и тогда разошлась именно она.

Все сломы откачены, `pytest` зелёный.
