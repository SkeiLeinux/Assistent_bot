## Блок A — контракт `specific_attrs`: фронт против реестра (P0)

### A1. LINK: `title` → `comment`

`lists.jsx:53` шлёт `{url, title}`. Реестр v0.4 (`specific_attrs.py:29`) знает `{url, comment?, tags?}`,
неизвестный ключ → `InvalidSpecificAttrs` → **422**. Сейчас ссылку с заполненным «Заголовком»
сохранить нельзя вообще.

По ТЗ §4.5: первичное поле `ListItem.text` = **Заголовок** (это UI-релейбл, поле уже есть),
`comment` = текст/комментарий. Кликабельная подпись = `text`, `href` = `url`.

Сделать: в `ATTR_SCHEMA.link` — `{ k: 'comment', label: 'Комментарий', kind: 'text' }` вместо `title`;
лейбл поля `text` на форме LINK — «Заголовок».

### A2. TASK: приоритет — выпадающий список

`lists.jsx:48` даёт `priority` свободным текстом; реестр требует член `TaskPriority`
(`low|medium|high|urgent|critical`), иначе 422. Любой ввод по-русски отказывает.

Сделать: `kind: 'select'` (нового вида в `ATTR_SCHEMA` пока нет — завести) со значениями enum и
UI-лейблами из ТЗ §4.5: низкий / средний / высокий / срочный / «ВОТПРЯМЩАССРОЧНОСУКА». Пусто =
без приоритета (ключ не отправляется — механика «пустые ключи опускаются» уже есть в `buildAttrs`).
Лейблы — UI-копи, значения в БД — только enum.

### A3. Кликабельный рендер LINK (#10 / P7)

В `lists.jsx` нет ни одного `href`. По ТЗ §4.5 это часть того же решения S3, а не отдельная фича:
подпись = `item.text`, ссылка = `specific_attrs.url`, комментарий — второй строкой. Открывать через
`window.Telegram.WebApp.openLink` (внешняя ссылка внутри Mini App иначе уводит из приложения).

### A4. Пин — иначе разъедется снова

Реестр живёт в питоне, его копия — литерал в jsx; сверки нет ни тестом, ни контрактом, и именно
поэтому расхождение прожило два месяца в проде. Завести тест (`tests/test_lists.py` или новый
`tests/test_frontend_contract.py`): вытащить `ATTR_SCHEMA` из `lists.jsx` регуляркой, собрать
**множества ключей по каждому типу** и сравнить с `_SCHEMAS` из `specific_attrs.py`.

Правило сравнения: множество ключей фронта ⊆ множество ключей реестра для каждого типа (фронт вправе
не показывать `tags`, но не вправе слать неизвестное). Плюс отдельная строгая проверка для `link` и
`task` — ключи, ради которых заход и делается.

То же самое для значений приоритета: набор `value` в селекте == набор `TaskPriority`.

Это тот же приём, что уже стоит на `openapi.yaml` ↔ `FLAG_*` (блок 14) и на сканере копий `WebAppData`
(смоук). Работает на тексте файла — jsx юнитами не тестируется, но набор ключей тестируется как текст.

### A5. Осиротевший `title` в данных

ТЗ v0.4 (changelog) требует: «осиротевший LINK-`title` бэкфиллится в `comment`». В коде и миграциях
следов бэкфилла нет. В локальной `life_manager.db` таких строк **0**, но локальная база — тестовая;
прод не проверен.

Сделать: скрипт-проверку (`scripts/`, разовый, read-only по умолчанию) — посчитать элементы LINK, у
которых в `specific_attrs` есть ключ `title`. Если на проде их 0 — записать это в отчёт и закрыть
пункт; если больше нуля — перенести `title` → `comment` тем же скриптом с флагом `--apply` и
артефактом «что изменено». Alembic-ревизию под это **не заводить**: это данные в JSON, а не схема.

## Блок B — Reminders v0.4 во фронте (P0)

В `reminders.jsx` **ноль** упоминаний `max_occurrences`, `until`, `delivery_target`, `fired_count`.
Бэкенд их принимает, валидирует и отдаёт в DTO (`api/routes.py:74–77, 108–120`). Сценарии S6
(«курс антибиотика — 10 раз каждые 8 ч») и S7 («напомнить партнёру») существуют только через API.

### B1. Условие остановки повторений (S1)

Поля в `ReminderEditor`, **показывать только при `recurrence !== 'none'`** (бэк отклоняет их при
`none` — `reminder_service.py:108`):

- «Остановить после N срабатываний» → `max_occurrences`, целое ≥ 1, пусто = без лимита;
- «Остановить после даты» → `until`, `datetime-local`.

**Важно про зону:** `until` слать **тем же преобразованием, что и `fire_at`** — `localInputToIso`
(наивная локальная строка, бэк переводит в UTC по `owner.timezone`). Отправить `until` через
`toISOString()` значило бы прислать UTC туда, где ждут локальное, и сдвинуть остановку на смещение
зоны. Обратно в форму — `isoToLocalInput`, как уже сделано для `next_fire_at`.

Валидация на бэке есть и вернёт 422 (`until` ≤ первого срабатывания; `max_occurrences < 1`) — фронт
обязан **показать текст ошибки**, а не проглотить; дублировать валидацию на фронте не нужно.

В строке списка (`ReminderRow`) — показывать прогресс, когда лимит задан: «3 из 10» (`fired_count` /
`max_occurrences`) и/или «до 01.09». Без этого пользователь не увидит, что курс кончается.

### B2. Адресат доставки (S2)

Поле «Кому напомнить» → `delivery_target`: пусто (по умолчанию — из `scope`) / «мне» (`owner`) /
«обоим» (`family`) / «партнёру» (`partner`).

`partner` в одиночной семье → бэк отдаёт **422** (I10) — показать текст ошибки как есть, поле не
прятать (состав семьи фронту неизвестен, а угадывать его отдельным запросом — лишний контракт).

Отличать в UI от «Видимости» (`scope`), которая уже есть: видимость — кто видит карточку, адресат —
кому уходит push. Это разные вещи по I6, и подпись поля обязана это говорить.

### B3. Ack повторяющегося больше не висит (баг B1 триажа)

`reminders.jsx:363` `doAck`: `setBusyId(rem.id)` сбрасывается **только в `catch`**. На успехе
`busyId` остаётся; для recurring карточка после `reload()` остаётся в списке (ACTIVE — так и
задумано по форку C), и спиннер не снимается никогда. Разовое напоминание уходит из списка, строка
размонтируется — поэтому баг «через один».

Сделать: `finally { setBusyId(null) }`. Тост для recurring — «Отмечено, повторится …», для разового —
«Отмечено выполненным» (текущий).

## Блок C — Поток 1: остальное

### C1. Push-кнопки не убираются (B2 триажа, #11)

`app/delivery/bot/setup.py:97`: `on_callback` вызывает `query.answer(...)` и **не трогает разметку**.
Кнопки живут вечно и жмутся повторно.

Сделать: после `dispatch` — снять клавиатуру у сообщения и дописать статус-строку («✅ Отмечено,
повторится …» / «✅ Выполнено» / «⏰ Отложено до …»).

Три обязательные оговорки:

1. Текст статуса знает **источник**, а не бот. Добавить поле в `CallbackResult`
   (`delivery/bot/callbacks.py`) — например `status_text: str = ""` — и заполнять его в обработчике
   Reminders. Хардкодить тексты напоминаний в диспетчере нельзя: он generic по ТЗ Notifications §7,
   и следующий префикс не должен требовать правки диспетчера.
2. Telegram на редактирование старого/неизменённого сообщения отвечает ошибкой
   (`TelegramBadRequest`, в т.ч. «message is not modified»). Она **не должна** ронять обработку:
   действие уже выполнено, откатывать его из-за косметики нельзя. Глушить точечно, с логом.
3. Идемпотентность: повторный тап по уже обработанному → ответ без эффекта. Частично это уже даёт
   `ReminderClosed` («Напоминание уже закрыто»), но **для recurring статус остаётся ACTIVE**, и
   повторный ack пройдёт снова. Разметку снимаем именно поэтому — но опираться только на неё нельзя
   (сообщение может не отредактироваться, см. п. 2).

### C2. Мультивыбор фото (B5 триажа, #7)

`screens.jsx:231` — единственный `<input type="file" accept="image/*">` **без `multiple`**; `onFile`
(`:203`) берёт `files[0]`. Общий `PhotoGrid` обслуживает и дневник, и создание блюда, `MAX_PHOTOS`
уже 10 и совпадает с `api_max_images`; батчи на бэке работают (блок 6 + блок 15).

Сделать: `multiple`; в `onFile` — обойти `e.target.files` целиком, взять **не больше свободных
слотов** (`max - photos.length`), сжимать последовательно (параллельный `fileToCompressedDataUrl` на
десяти кадрах в WebView — верный способ получить OOM).

Попутно: `catch (_) {}` в `onFile` глушит ошибку сжатия молча — пользователь видит, что фото просто
не добавилось. Заменить на тост. Молчаливая деградация — ровно тот класс дефекта, который в этом
проекте уже стоил волны замеров.

### C3. Шапка «План/факт» в Finance (B3 триажа, #13b)

CSS в `finance.jsx` (строка ~933+): `.fin-total__row {display:grid; grid-template-columns:1fr 1fr 1fr; gap:8px}`,
`.fin-total__val {font-size:16px; font-weight:700}` — без `min-width:0`, без `nowrap`, без табличных
цифр. На 360–380 px значения со знаком не помещаются и наезжают на соседей.

Сделать: `min-width:0` на `.fin-total__cell`, `white-space:nowrap` + `font-variant-numeric: tabular-nums`
на `.fin-total__val`, уменьшение кегля на узких ширинах (`clamp` или медиа-запрос).
Проверка — глазами на 360 px, скрин до/после в отчёт.

- **`tags`** (реестр допускает для TASK/IDEA/GIFT/LINK). Осознанно вне объёма — это новый UI-элемент,
  а не приведение к контракту. Назвать в отчёте как невзятое.
- **Домен еды**, кроме `multiple` в `PhotoGrid`. Волна 2 и ярус B заморожены (решение С. 2026-08-14).
- **Схема БД.** Ни одной Alembic-ревизии в этом заходе. Если кажется, что нужна — это сигнал, что
  задача понята неверно.

## Порядок

смоук** `scripts/smoke.py` (он про еду и этих правок не касается, но проверяет, что выкатка живая).
