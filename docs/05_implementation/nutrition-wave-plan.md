### 1.3 Приёмка

| Метрика | Baseline | Порог |
|---|---|---|
| валидный JSON | 100% | 100% |
| kcal ≤2% | 92% | **≥92%** |
| БЖУ ≤2% | 83% | ≥83% |
| кДж-конфузий | 0 | 0 |
| медианная задержка | 1.3 с | ≤2.0 с |
| «отказ вместо выдумки» на A-07 | — | `readout ∈ {estimate, unreadable}` |
| **точность переранжирования** | — | **≥80% верных при нуле уверенных ошибок** (ADR-0019 §6) |

Раннер обязан уметь прогнать **обе** версии промпта — иначе «не хуже» недоказуемо.

**Факт приёмки (2026-08-03, перепрогон v3 промпта на VPS):** JSON 100 % · kcal ≤2 % — 92 % · БЖУ ≤2 % — 84 % · кДж-конфузий 0 · медиана 1.6 с. Все пороги взяты.

Две строки таблицы закрыты иначе, чем задумано, и обе — сознательно:

- **точность переранжирования** — гейт **закрыт отрицательно** пятью механизмами на одной выдаче (01–02.08); блоки 7–10 не отгружены, развилка снята вариантом D. Метрика к волне 1 больше не применяется;
- **«отказ вместо выдумки» на A-07** — **снят из гейта 2026-08-10** и переведён в наблюдаемую величину. Знаменатель равен единице, а сам кейс помечен `unscorable`: метрика на одном кейсе проходится подбрасыванием монеты, что противоречит правилу §5 ниже. Ужесточать под неё промпт нельзя без цены — `readout` трёхзначен, сдвиг в сторону отказа бьёт по `kcal ≤2 %`. Возврат в гейт — при ≥5 нечитаемых кадрах; знаменатель копится сам из логов блока 13 (доля `unreadable` в поле).

Плюс полный `pytest` без регрессов (62 теста Nutrition), `import-linter` зелёный, `resolve` остаётся leaf.

### 1.4 Что НЕ входит

Веб-ступень, пересчёт бюджета лестницы, продуктовые фиксы из триажа (S5 единицы порций, S6 пересчёт состава, P1, P2), ярусы B/C датасета.

|---|---|---|
| eval-прогон | «порог не прошёл никто» | рассинхрон фото↔эталон в 11 кейсах |
| калибровка | распределение по 25 точкам | фильтр по `reasoning_effort` отбросил 3 прогона из 4 |
| источник OFF | «покрытие 8%», затем «100%» | HTTP 503; затем — Elasticsearch всегда возвращает топ-20 |

Во всех трёх случаях результат был **внутренне согласован** и потому не выглядел подозрительно. Ловилось только независимой проверкой: детектор рассинхрона по консенсусу названий, распределение на эталонах, ранг верной карточки в выдаче.

**Правило в DoD:** замер принимается вместе с проверкой, которая опровергла бы его число, если бы оно было неверным. Отсутствие такой проверки — незакрытый пункт, а не мелочь.

**Развитие правила (2026-07-30, при проектировании ярусов B/C).** На ярусе A портились данные, и опровергающей проверкой стал детектор рассинхрона по консенсусу названий. На ярусах B и C печатной истины почти нет, зато метрики сложнее — поэтому основной риск смещается **с данных на метрики**: метрика, пропускающая заведомо неверный ответ, даст правдоподобное и бесполезное число.

**Развитие правила (2026-08-02, по итогам пятого замера механизма выбора).** Когда на одной и той же выборке проверяется механизм за механизмом, добавляется риск, которого нет у первого замера: результат «на этот раз порог взят» становится неотличим от подгонки под N точек. Поэтому — **правило решения (порог, правило верности, что означает провал) записывается в отчёт до прогона, и там же указывается, попытка ли это последняя**. Правило, написанное после того, как увидены числа, правилом не является. Практическое следствие, применённое в `veto-accuracy-2026-08-02.md`: идея, возникшая по ходу замера, идёт в отчёт как гипотеза, требующая **новых данных**, а не как повод на ещё один прогон по тем же кейсам. Там же — второе следствие: если метрика содержит подпись (близость ккал), информацию о которой можно подсунуть механизму на вход, **основным считается режим без этой информации**, иначе метрика мерит саму себя; расхождение с «информированным» режимом и есть измеренная циркулярность.

Соответственно правило расширено: **метрика не считается введённой, пока в наборе тестов нет негативного контроля — синтетически испорченного ответа, который она обязана забраковать** (`llm-eval-dataset.md` §3D.1). Ключевой мутант — «две компенсирующие ошибки»: один ингредиент ×2, другой ×0.5, итог сходится при полностью неверном разборе. Метрика по итоговому числу его пропускает; поингредиентная — ловит. Именно по этой причине порог «итог ≤5%» из эскиза яруса C отменён.
