# Задача для Claude Code: вариант D — поиск OFF удаляется, остаётся штрихкод

Это текст для вставки в Claude Code. Ниже — задание целиком, без сокращений.

---

## Контекст

Прочитай перед началом:

- `docs/05_implementation/off-value-2026-08-03.md` — замер, по итогам которого принято решение
- `docs/03_architecture/adr/ADR-0019-off-source-and-matching.md` — ревизия 2026-08-03 (вариант D)
- `docs/04_specs/spec-nutrition-retrieval.md` v0.7 §4, §7.1
- `docs/04_specs/spec-nutrition-llm-contract.md` §7.1a

Коротко: шесть замеров показали, что поисковая ветка OFF выбирает **чужой товар**. На ветке `estimate`
она проигрывает типовым числам модели 7:13, грубых промахов 11 из 25 (515 %, 461 %, 381 %). Решение С.
от 2026-08-03 — вариант D: поисковый запрос к OFF не выполняется вообще, остаётся только точный lookup
по штрихкоду. Это закрывает блоки 7–10 волны 1: 7 и 9 отменены, 8 и 10 реализуются в урезанном виде.

## Что сделать

### 1. Убрать поисковую ветку

- `app/contexts/nutrition/resolve/sources/openfoodfacts.py`: удалить всё, что обслуживает
  `cgi/search.pl` — построение `search_terms`, разбор списка продуктов, выбор кандидата
  (`select_best`, `score_of`, `_first_brand` в части поиска). Модуль остаётся, но умеет **только**
  lookup по коду.
- `app/contexts/nutrition/resolve/__init__.py::build_resolver()`: в `network_sources` — источник
  штрихкода, а не поиска.
- `app/config.py`: `off_lc` удалить (локаль была параметром поиска). `off_base_url` оставить,
  добавить путь `api/v2/product/<code>` в адаптере. `off_timeout_s` и `off_user_agent` остаются.

### 2. Реализовать lookup по штрихкоду (блок 8)

- Эндпоинт `GET {off_base_url}/api/v2/product/{barcode}?fields=…`. Он **работает** и не затронут
  поломкой Perl-бэкенда, положившей поиск. Форма ответа `{status, product}`, поля
  `nutriments.energy-kcal_100g / proteins_100g / fat_100g / carbohydrates_100g`.
- Вызывать **только** если `item.barcode` не `None` **и** прошёл C4.0 — `ean_checksum_ok()` в
  `resolve/checks.py` уже реализована, использовать её, не писать заново.
- Нет штрихкода, не прошёл контроль, `status != 1`, неполные КБЖУ, таймаут → ступень возвращает
  `None` и позиция уходит в `estimate`. Никаких «похожих товаров».

### 3. Гейт уверенности (блок 10, урезанный)

- Добавить поле `match_confidence: str | None` в `ResolvedNutrition` (`resolve/ports.py`).
- Источник штрихкода проставляет `"exact"`. Других значений не бывает: `confirmed` **упразднено**,
  порождать его нечем.
- `resolve/pipeline.py::match_confidence()` перестаёт быть заглушкой — читает поле. `CONFIDENT_MATCHES`
  сократить до `("exact",)`. Докстринг переписать: он сейчас описывает отменённую развилку.
- Сверка label-preferred (§7.2) после этого начинает реально работать — но только на позициях со
  штрихкодом, это ~16 % (ADR-0019). Логику сверки не трогать, она уже написана.

## Чего в этом заходе НЕ делать

- Не мигрировать на `search-a-licious` — §2.1 ADR-0019 **отменена** вместе с поиском.
- Не трогать `energy_kj_100g` и проверку C3a (ТЗ контракта v0.5) — отдельный заход вместе с блоком 11.
- Не трогать таймаут LLM, ретраи, вторичный таргет, startup-guard — это блок 11.
- Не трогать кап `[:5]` в `api/routes.py` — это блок 15.
- Схему БД не менять, миграций в этой задаче нет.

## DoD

1. `pytest` зелёный целиком, регрессов в тестах Nutrition нет.
2. `lint-imports` — 8/8, `resolve` остаётся leaf внутри Nutrition.
3. Новые тесты (без сети, на фейковом источнике):
   - позиция **без** штрихкода → сетевой вызов **не делается вовсе** (проверять счётчиком вызовов
     фейка, а не результатом);
   - штрихкод не прошёл C4.0 → вызова нет, `estimate`;
   - штрихкод валиден, источник ответил → `source="off"`, `match_confidence="exact"`;
   - `label` + валидный штрихкод + расхождение > 15 % → флаг `label_disagrees_with_source` и
     `alternative` заполнен (сверка ожила);
   - `label` **без** штрихкода → сверка не запускается, вызова нет.
4. Grep-тест: в кодовой базе не осталось обращений к `cgi/search.pl` и `search.openfoodfacts.org`.
5. Живых вызовов OFF в `pytest` нет.

## Замечание по стилю комментариев

В коде документируй **почему**, а не «что». Для этой задачи существенно: удаление поиска — не уборка
мёртвого кода, а результат шести замеров; человек, читающий код через полгода, должен понимать, что
поисковую ветку возвращать не надо, и где лежит обоснование. Ссылку на `off-value-2026-08-03.md`
поставить в докстринг адаптера.
