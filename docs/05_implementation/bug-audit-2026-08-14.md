## 0. Главная находка: фронт отстал от бэка на Поток 2, и это не «недоделка», а сломанный сценарий

`CLAUDE.md` (запись 2026-06-20) фиксирует: Поток 2 (Lists v0.4 + Reminders v0.4) реализован, **осталось «фронт jsx, git rm транзита, alembic upgrade, полный pytest, коммит»**. Бэкенд и миграция (`b7c9d1e2f3a4`) уехали в прод. **Фронт — нет.** Последствие сильнее, чем «фича не видна»:

**L-01 (P0). Ссылку с заголовком нельзя сохранить — 422.**
`lists.jsx:53` шлёт `specific_attrs: {url, title}`. Бэкенд v0.4 (`services/specific_attrs.py:29`) знает для LINK только `{url, comment, tags}`, а неизвестный ключ — жёсткий отказ: `InvalidSpecificAttrs("Недопустимые поля для типа link: title. Допустимо: comment, tags, url")` → 422. То есть **основной сценарий типа LINK (#9/S3, ради которого правился ТЗ) в проде отказывает**, если пользователь заполнил поле «Заголовок».
Воспроизведение: Списки → тип «Ссылки» → создать элемент, заполнить «Заголовок» → сохранить.
Фикс: `title` → `comment`, лейблы по ТЗ v0.4 (`item.text` = Заголовок, `comment` = комментарий).

**L-02 (P0). Приоритет задачи нельзя сохранить — 422.**
`lists.jsx:48` даёт `priority` свободным текстом (`kind: 'text'`), бэкенд v0.4 требует член `TaskPriority` (`low|medium|high|urgent|critical`) и иначе отказывает. Любой ввод по-русски («высокий») → 422.
Фикс: выпадающий список из пяти значений (это и есть #14a/S4, он же закрывает половину задачи).

**R-01 (P0). Reminders v0.4 недоступны из Mini App.**
В `reminders.jsx` **ноль** упоминаний `max_occurrences`, `until`, `delivery_target`. Бэк их принимает и отдаёт (`contexts/reminders/api/routes.py:74–112`), фронт не показывает и не шлёт → условие остановки повторений (#2/S1) и адресат доставки (#12/S2) существуют только в API.
Фикс: поля в редакторе напоминания + отображение в строке списка.

> **Почему это не поймали.** Контракт `specific_attrs` — реестр в питоне, его копия — литерал в jsx; сверки между ними нет ни тестом, ни контрактом. Это ровно тот класс, который в проекте уже дважды чинился пином (`openapi.yaml` ↔ `FLAG_*`, копия HMAC ↔ `WebAppData`). Рекомендация в §3.

## 3. Что предлагаю к фиксу и в каком порядке

**Батч 1 — «фронт догоняет бэк» (P0, один заход, миграций нет).**
L-01, L-02, R-01 — сломанные/невидимые сценарии принятых ТЗ v0.4. Плюс пин, чтобы это не повторилось: тест, который вытаскивает `ATTR_SCHEMA` из `lists.jsx` регуляркой и сверяет **множества ключей по каждому типу** с `_SCHEMAS` из `specific_attrs.py`, с мутантами в обе стороны («лишний ключ во фронте» / «ключ пропал»). Это тот же приём, что уже стоит на `openapi.yaml` ↔ `FLAG_*` и на копии HMAC; jsx не тестируется юнитами, но **набор ключей — тестируется как текст**.

**Батч 2 — Поток 1 (P0/P1, один заход).**
B1 (`finally`), B2 (снятие разметки + идемпотентность callback), B5 (`multiple`), B3 (CSS). B1/B2/B5 — с тестами (для B2 — повторный callback не меняет состояние и разметка снята); B3 — визуально, скрин до/после на 360 px.

**Батч 3 — переход к модулям вне еды.** После двух батчей открытым продуктовым остатком по не-еде остаются: #10/P7 (кликабельные ссылки — в `lists.jsx` нет ни одного `href`), #13a/P6 (выбор дня/недели в Finance — бэк умеет `from`/`to`), #6b/P3 (reload кидает на главную: `app.jsx:40` держит экран в `useState` без персиста), теги в списках (бэк принимает `tags` для TASK/IDEA/GIFT/LINK, фронт не показывает). Это уже не баги, а объём — состав и порядок стоит собрать отдельно, вместе с Катей.

**Не в этот цикл:** S5 (именованные порции) и S6 (пересчёт состава при смене веса блюда) — оба **не начаты в коде** (в `contexts/nutrition` нет ни `serving`, ни `recipe_weight`/масштабирования), оба — домен еды, оба требуют правки ТЗ до кода.
