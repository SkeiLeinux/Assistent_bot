## Часть 1. Блок 13 — наблюдаемость (§9)

### 1.1 Строка на каждый LLM-вызов

Формат — из §9 дословно, уровень INFO:

```
llm_call model=<> target=<primary|fallback> path=<analyze_photo|dish_combined|...>
         batch=<i/n> latency_ms=<> prompt_tokens=<> completion_tokens=<>
         finish_reason=<> n_items=<> readout={label:2,estimate:1,unreadable:0}
         flags=[arith_mismatch,...] retries=<>
```

### 1.2 Строка на разбор целиком

`sources={label:2,off:1,estimate:1}`, `total_ms`, `budget_exhausted=<bool>`.

### 1.3 Алерты (существующий механизм error-handler)

- первое за сутки переключение на вторичный таргет;
- провал startup-guard.

Обе точки уже есть в коде после блока 11 — сюда добавляется только логирование рядом с ними.

### 1.4 Требования к реализации

- **Структурированная строка, не f-string россыпью.** Один хелпер, собирающий `key=value`; поля
  добавляются в одном месте. Иначе следующий человек добавит поле в один из пяти путей и разъедется.
- **Ключ не логируется никогда** — ни целиком, ни хвостом. Это тот же класс, что утечка в `journalctl`.
- **Не логировать содержимое ответа модели и текст пользователя.** Это дневник питания двух живых
  людей; в лог идут только счётчики и коды.
- Уровень INFO, но **не в цикле по позициям** — одна строка на вызов и одна на разбор, иначе тарелка
  из шести позиций даст простыню.
- SQLAlchemy сейчас логирует каждый SQL на INFO (видно в `journalctl` при рестарте). Если это мешает
  читать новые строки — приглуши `sqlalchemy.engine` до WARNING в конфиге логирования. Это не «а заодно
  почистим», а условие того, чтобы новые строки было видно.

## Часть 2. Хвост №4 — артефакты замеров в чужом каталоге

`scripts/check_off_*.py` пишут результаты в `tests/eval/runs/` — каталог прогонов раннера. Из-за этого
`report` раннера дважды падал на посторонних файлах.

- завести отдельный каталог (например `tests/eval/probes/`), перенести туда запись всех
  `scripts/check_off_*.py`;
- существующие артефакты замеров OFF **переместить**, не копировать;
- проверить, что структурный тест `report` (заведён в блоке 11) остаётся зелёным.

## Часть 3. Хвост №5 — версия промпта не видна в имени артефакта

Тег версии промпта попадает в имя файла прогона только когда версия не дефолтная, поэтому
`2026-08-03_gpt-5.4-mini.json` не выдаёт, что он снят на v3. Через месяц это неотличимо от v2.

- **версия промпта пишется всегда** — и в имя файла, и в поле внутри JSON;
- переименовывать уже снятые артефакты **не надо** — они описаны в отчётах; вместо этого добавь в
  README каталога строку о том, с какой даты тег обязателен и что снято раньше.
