## Открытые вопросы фазы архитектуры

1. ✅ **Модель видимости** — закрыт **ADR-0001**: Вариант A (`scope` + `hidden_from`), персистенция `hidden_from` — join-таблица `shareable_hidden_from` (под-решение H3).
2. ✅ **Механизм импорта финансов** — закрыт **ADR-0002**: загрузка `.xlsx` (A1) + структурный парсинг (P2) + алиас-нормализация таксономии; промежуточное представление → валидация (родитель = сумма детей, дневная матрица) → идемпотентный upsert по месяцу; fail-loud ACL. Sheets API / конфиг-маппинг — North Star.
3. ✅ **Планировщик напоминаний** — закрыт **ADR-0003**: собственный async poll-loop в одном event-loop, `Reminder` = SSOT; misfire — догнать-в-грейсе-затем-skip; recurrence простой. Каденс/состав дайджеста — продуктовый вход (Катя).
4. ✅ **Изоляция контекстов в коде** — закрыт **ADR-0004**: Вариант B (пакет-на-контекст + общий `kernel` + enforced allowed-edges через `import-linter` из графа `DOMAIN_MODEL.md` §2).
5. ✅ **Тайминг миграции на PostgreSQL** — закрыт **ADR-0005**: SQLite в MVP, код портируемый; миграция по явному триггеру (мультипроцесс/standalone, реальные данные, рост, Postgres-only фича).

## Недоспецификации (вход в ADR/ТЗ, не блокеры анализа)

Выявлены при ревью готовности к ADR; уровень ADR/ТЗ, архитектуру не блокируют.

- **Каденс/триггер ретро-дайджеста** — механизм поддержан **ADR-0003** (периодическая job); конкретный каденс — **продуктовое решение (Катя)**, по умолчанию предложено еженедельно/вечер.
- **Источники ретро-дайджеста** — нужна ли в дайджесте сводка напоминаний. **→ Решено: НЕ включать сводку напоминаний** (Катя, 2026-06-07; ТЗ Analytics I5). Состав дайджеста — Списки+Финансы+Питание.
- **Семантика напоминаний** — recurrence решён в **ADR-0003** (`none/daily/weekly/interval`); недоставка push (ретрай + алерт админу), ack/snooze — уровень ТЗ Reminders/Notifications.

- **2026-07-28 (ADR-0019 принят; ревизия ADR-0013 уточнена):** замер источника OFF с прод-машины (`05_implementation/off-source-probe-2026-07-28.md`) вскрыл, что **поисковая ступень лестницы ADR-0013 в проде не работала никогда**: легаси-эндпоинт `/cgi/search.pl` (и `/api/v2/search`) отдаёт HTTP 503 — общий Perl-бэкенд OFF устарел. Провенанс `source=off` был недостижимым состоянием, а резолвер сводился к `label → estimate`; незаметно из-за отсутствия наблюдаемости (D12). Это же объясняет открытые пункты триажа 15c и §5.1. **Покрытие базы при этом хорошее — 20 из 25 товаров присутствуют**, то есть проблема не в источнике данных, а в двух других местах: транспорт (мёртвый эндпоинт) и матчинг (`select_best` выбирает верную карточку в 36% случаев, точность не растёт ни при каком пороге — скор с правильностью не коррелирует и местами инвертирован). Гипотеза «добавить `min_score`», выдвинутая до замера, **опровергнута данными**. Заведён **ADR-0019**: миграция на `search-a-licious` (другой запрос, другая форма ответа — `_first_brand` падает на списке, `product_name_ru` не существует), barcode-first с проверкой контрольной суммы EAN, **LLM-переранжирование** кандидатов батчем на разбор, `match_confidence` и право ступени на отказ вместо «похожего товара». Ревизия ADR-0013 уточнена **гейтом уверенности**: сверка label-preferred запускается только при `match_confidence ∈ {exact, confirmed}` — при точности матчинга 36% она иначе производила бы ложные расхождения чаще, чем ловила настоящие. Миграция OFF переезжает в волну 1. Замер занял 4 итерации, первые три дали недействительные числа одного класса — правдоподобные, но измеряющие не то (разбор — §4 отчёта).
- **2026-07-27 (ADR-0018 принят + ревизия ADR-0013):** заведено ТЗ `04_specs/spec-nutrition-llm-contract.md` (промпты, структура запроса, проверки ответа, отказоустойчивость) — 14 дефектов по коду, 6 вопросов, все закрыты С. в тот же день. Из них два архитектурных. **(1) ADR-0018** «Отказоустойчивость LLM-провайдера», вариант **B**: вторичный таргет `gpt-5.4` у того же вендора вместо Groq. Рекомендация Claude (A, другой вендор) отклонена — резерв с точностью 76% выдаёт молча неверные КБЖУ, что хуже честного отказа, а фактический инцидент 17.07.26 был модельного, не вендорского уровня. При внесении решения выявлено следствие общего ключа: матрица переключения сужена до отказов модельного уровня (401/`insufficient_quota`/org-429 резервом не лечатся). **(2) Ревизия ADR-0013**: правило №1 лестницы изменено с label-short-circuit на **label-preferred** — замер показал, что на ~8% этикеток модель верно называет продукт и ошибается в числах на 5–35%, получая при этом высший провенанс `source=label`; теперь позиции с брендом сверяются с OFF, расхождение >15% показывается пользователю. Побочное следствие обоих решений — **Groq уходит из кода целиком** (оба таргета ходят по OpenAI-compat).
- **2026-07-27 (ADR-0017 принят):** L1 закрыт замером — **vision-модель `gpt-5.4-mini`** (92% kcal-hit на 25 валидных кейсах, 1.3 с, $0.41/мес; паритет с `gpt-5.4` при цене втрое ниже). Абстракция §6 упростилась до `base_url` в конфиге — адаптер под Anthropic не понадобился. Отчёт — `05_implementation/llm-eval-results-2026-07-27.md`. Остаётся внедрение в прод отдельным инкрементом.
