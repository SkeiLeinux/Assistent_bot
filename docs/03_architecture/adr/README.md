## Открытые вопросы фазы архитектуры

1. ✅ **Модель видимости** — закрыт **ADR-0001**: Вариант A (`scope` + `hidden_from`), персистенция `hidden_from` — join-таблица `shareable_hidden_from` (под-решение H3).
2. ✅ **Механизм импорта финансов** — закрыт **ADR-0002**: загрузка `.xlsx` (A1) + структурный парсинг (P2) + алиас-нормализация таксономии; промежуточное представление → валидация (родитель = сумма детей, дневная матрица) → идемпотентный upsert по месяцу; fail-loud ACL. Sheets API / конфиг-маппинг — North Star.
3. ✅ **Планировщик напоминаний** — закрыт **ADR-0003**: собственный async poll-loop в одном event-loop, `Reminder` = SSOT; misfire — догнать-в-грейсе-затем-skip; recurrence простой. Каденс/состав дайджеста — продуктовый вход (Катя).
4. ✅ **Изоляция контекстов в коде** — закрыт **ADR-0004**: Вариант B (пакет-на-контекст + общий `kernel` + enforced allowed-edges через `import-linter` из графа `DOMAIN_MODEL.md` §2).
5. ✅ **Тайминг миграции на PostgreSQL** — закрыт **ADR-0005**: SQLite в MVP, код портируемый; миграция по явному триггеру (мультипроцесс/standalone, реальные данные, рост, Postgres-only фича).

## Недоспецификации (вход в ADR/ТЗ, не блокеры анализа)

Выявлены при ревью готовности к ADR; уровень ADR/ТЗ, архитектуру не блокируют.

- **Каденс/триггер ретро-дайджеста** — механизм поддержан **ADR-0003** (периодическая job); конкретный каденс — **продуктовое решение (Катя)**, по умолчанию предложено еженедельно/вечер.
- **Источники ретро-дайджеста** — нужна ли в дайджесте сводка напоминаний. **→ Решено: НЕ включать сводку напоминаний** (Катя, 2026-06-07; ТЗ Analytics I5). Состав дайджеста — Списки+Финансы+Питание.
- **Семантика напоминаний** — recurrence решён в **ADR-0003** (`none/daily/weekly/interval`); недоставка push (ретрай + алерт админу), ack/snooze — уровень ТЗ Reminders/Notifications.
