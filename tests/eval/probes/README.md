# `tests/eval/probes/` — артефакты ЗАМЕРОВ источника

Сюда пишут `scripts/check_off_*.py` — разовые замеры, отвечающие на вопрос
«годится ли механизм», а не «какова точность модели». У каждого своя форма, свой
план и свой отчёт в `docs/05_implementation/`; общего формата у них нет и не
предполагается.

Каталог заведён в блоке 13 (2026-08-03). До него замеры складывали результаты в
`tests/eval/runs/` — каталог прогонов раннера, — и сводка раннера дважды падала
на них `KeyError`: у файлов другая форма, а `build_report` читает всё, что видит.
Оба падения чинились «по ключу» (`records`, потом `provider`), то есть по
симптому конкретного файла. Настоящая причина — общий каталог у двух
инструментов с разными контрактами; она закрыта здесь.

| файл | замер | отчёт |
|---|---|---|
| `2026-08-01_off-rerank.{json,txt}` | LLM-переранжирование топ-10 (4 режима) | `rerank-accuracy-2026-08-01.md` |
| `2026-08-02_off-veto.{json,txt}` | «топ-1 + LLM-вето» | `veto-accuracy-2026-08-02.md` |
| `2026-08-03_memory-tierA.json` | типовые числа модели по названию (рука M) | `off-value-2026-08-03.md` |
| `2026-08-03_off-value.json` | польза ступени OFF на ветке `estimate` | `off-value-2026-08-03.md` |

Файлы перемещены сюда из `runs/`, а не скопированы: две копии одного артефакта
разъезжаются, и через месяц неизвестно, какая из них дала числа отчёта.

`2026-08-01_off-rerank.json` продолжает читаться как КЭШ ВЫДАЧИ последующими
замерами (`check_off_veto.py`, `check_off_value.py`) — это не архив, а условие
сравнимости: механизмы обязаны сравниваться на одной выдаче OFF, а не в
нескольких прогонах.
